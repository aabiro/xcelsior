# Bug audit in progress

Scope: investigate the cross-worker quota/test-isolation failures, then audit
the remaining backend, frontend, MCP, and desktop behavior for bugs, stubs,
and incomplete functionality. Passing a narrow suite does not complete this
audit. Production deployment and live acceptance have not been performed.

## Reproduced and fixed

- Auth regression tests inherited a 100,000-request quota from the global
  fixture. Pin normal quotas after that fixture, isolate local fallback
  buckets, and check shared state, window boundaries, and fallback behavior.
- Support chat and the AI assistant counted provider requests per process.
  They now use shared runtime state, with locked local fallback during an
  outage. Test cleanup includes their durable namespaces.
- AI chat and analytics consumed two slots per HTTP request. The route now
  passes its admission decision to the stream; direct stream callers still
  enforce the limit.
- AI approval resolution used the signed token instead of the stored ID in
  its UPDATE and did not lock the pending row. Real PostgreSQL tests reproduced
  repeated tool execution and two concurrent claimants. Resolution now locks
  the row and persists the decoded ID. Expiry is committed before returning
  a shared quota slot, avoiding a nested pool checkout.
- Support chat history and continuation accepted another user's conversation
  ID. Both paths now require the authenticated owner, and missing/expired IDs
  return 404. New conversations receive server-generated IDs.
- Chat feedback accepted arbitrary or foreign message IDs. Completed streams
  and history now expose persisted message IDs, the browser retains them, and
  feedback insertion verifies message ownership and the assistant role.
- Selecting saved chat history updated localStorage but left the stream hook
  pointing at a new conversation. Restoring history now updates both states.
- A cleared request could finish after a new request and change its streaming
  state or restore obsolete content. Aborted responses are ignored and only
  the current request may reset streaming state.

Additional fixes in the current worktree:

- Support chat stores conversation IDs per authenticated account. Changing
  accounts remounts the widget, clearing private messages, unsent input,
  feedback, and history-drawer state. The unowned legacy storage key is ignored.
- Unmounting or changing accounts aborts pending streams and history loads.
  History selection, clearing, and streaming share cancellation ownership, so
  a late response cannot overwrite newer content or reset another request's
  loading state. The guard also prevents duplicate sends before React renders.
- History failures are visible; inaccessible IDs are cleared. The composer is
  disabled while loading history, and the clear control can cancel that load.
- The instance cost card used nonexistent `rate_per_hour`/`total_cost` fields
  and estimated elapsed billing time in the browser, including paused time.
  It now consumes the typed `rate_per_hour_cad`, `cost_cad`, and
  `rate_is_estimate` API fields. Missing/nonfinite amounts are unavailable;
  actual zero remains zero. API estimates are not labelled total billed cost.
- Fixed two existing TypeScript failures: the missing `afterEach` test import
  and the undefined `outline` badge variant.
