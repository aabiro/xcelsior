Connect supported AI assistants and agentic tools to your Xcelsior account with our [Model Context Protocol](https://modelcontextprotocol.io/) server. The Xcelsior MCP lets an assistant securely inspect fleet availability, launch and manage GPU instances, attach storage volumes, run serverless inference, check wallet balances, and settle provider payouts on your behalf, using your existing Xcelsior login and scoped permissions.

This guide covers connecting your AI client to your Xcelsior account (`https://mcp.xcelsior.ca/mcp`) as well as connecting AI assistants to Xcelsior documentation (`llms.txt`, OpenAPI, and built-in documentation search). For in-app natural-language orchestration without configuring an external MCP client, see [LLM Integration](/llm-integration#xcel-ai-the-in-app-assistant).

## Xcelsior MCP capabilities

You can use Xcelsior MCP to help an AI assistant:

- Browse live GPU availability, spot prices, reference rates, and marketplace listings.
- Quote, launch, monitor, and terminate interactive GPU instances, training jobs, pipelines, and image sweeps.
- Manage SSH public keys and open authenticated terminal access to running instances.
- Create, attach, detach, snapshot, and restore persistent storage volumes and promote job artifacts.
- Deploy and invoke serverless inference endpoints and inspect endpoint health.
- Check wallet balances, spend runway, invoices, payment methods, and funding options (Card, Bitcoin, Lightning, PayPal).
- Track provider reputation, claim earned milestones, inspect earnings across Stripe Connect, PayPal, and Wise, and queue completed jobs for payout.

### Built-in spend and safety boundaries

Unlike read-only MCP servers, Xcelsior MCP can operate infrastructure — but **every action that spends money or destroys state is gated**:

- **Binding quotes before spend**: Tools that launch compute (`create_instance`, `create_serverless_endpoint`, `run_pipeline`, `create_image_sweep`, `widening auto-top-up`) default to quoting a plan (`dry_run: true`) or returning an `approval_required` launch plan (`plan_id`) that a human approves before money is committed.
- **Explicit confirmation for destructive actions**: Tools that terminate instances, delete volumes, overwrite a volume from a snapshot, or cancel inference jobs require `confirm: true` and carry `destructiveHint: true`.
- **Human-only payout destination and approval controls**: An MCP client can check provider payout status (`get_provider_account`, `get_paypal_status`, `get_wise_status`) and settle a completed job onto an already-configured rail (`request_provider_payout`), but **cannot** change where payouts are sent (`POST /api/providers/{id}/wise/recipient`, Stripe/PayPal onboarding links) or approve Wise payout batches (`POST /api/admin/wise/payouts/{id}/approve`). Those actions require an interactive browser session.

## Supported AI agents

Xcelsior MCP works with any MCP client that supports **Streamable HTTP** (`2025-03-26`) and **OAuth 2.1 with PKCE**, including:

- Claude Code
- Claude Desktop
- ChatGPT
- Codex CLI
- Cursor

## Important: Before you begin

When you connect an AI assistant, it can request information and invoke tools within the scopes you approve. Depending on the permissions granted, this may include running instances, SSH public keys, volume metadata, wallet balances, invoice history, and provider earnings.

Xcelsior controls access to your account through MCP and validates scopes on every request. The AI assistant is operated by a separate provider, which handles information it receives under its own terms and privacy policy, including how conversation context and tool outputs may be stored or used.

Only grant the scopes your workflow needs, and review your AI provider's privacy practices before connecting.

**Never share Xcelsior passwords, one-time passcodes, MFA backup codes, or private SSH keys with an AI assistant.** A legitimate Xcelsior MCP connection redirects you to an Xcelsior-hosted page to sign in and grant consent.

## Requirements

- An Xcelsior account.
- Access to a supported MCP client that allows remote Streamable HTTP servers and OAuth 2.1.
- Network access to `https://mcp.xcelsior.ca/mcp` (and `https://xcelsior.ca` for OAuth discovery and token exchange).

## Connect to Xcelsior MCP

Use the following server URL in your MCP client: `https://mcp.xcelsior.ca/mcp`

### Claude Code

Run this command in your terminal:

```bash
claude mcp add --transport http xcelsior https://mcp.xcelsior.ca/mcp
```

### Codex CLI

Run this command in your terminal:

```bash
codex mcp add xcelsior --url https://mcp.xcelsior.ca/mcp
```

### ChatGPT

1. Go to **Settings → Plugins → MCPs** (or **Connectors**).
2. Click **Add**, then **Add MCP server**.
3. Use `xcelsior` as the name, select **Streamable HTTP**, and paste the server URL: `https://mcp.xcelsior.ca/mcp`
4. Click **Save** and complete the Xcelsior-hosted authentication.
5. Start chatting.

### Claude Desktop

1. Open **Settings → Developer → Edit Config**.
2. Add the server configuration below, keeping any existing entries.
3. Save the file and restart Claude Desktop.

```json
{
  "mcpServers": {
    "xcelsior": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://mcp.xcelsior.ca/mcp"
      ]
    }
  }
}
```

### Cursor

Add `xcelsior` to `.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "xcelsior": {
      "url": "https://mcp.xcelsior.ca/mcp"
    }
  }
}
```

After adding the server, start your client's MCP authentication flow (`/mcp` in Claude Code, or `codex mcp login xcelsior` in Codex CLI).

## Sign in and grant access

Xcelsior MCP uses OAuth 2.1 with PKCE and RFC 9728 Protected Resource Metadata (`https://mcp.xcelsior.ca/.well-known/oauth-protected-resource`). You do not need to manually paste an API token for interactive clients.

When you connect, your client opens an Xcelsior-hosted sign-in and consent page:

1. Sign in to Xcelsior and complete any required MFA checks.
2. Review the client requesting access.
3. Review and select the permission scopes you want to grant.
4. Confirm the connection.

For headless automation or CI pipelines that cannot open a browser, you can also mint a scoped machine client under **Dashboard → Settings → Connect AI Agents** (`client_credentials` grant with `resource=https://mcp.xcelsior.ca/mcp`).

> **Note on Quick Connect tokens:** The one-click Quick Connect credential intentionally withholds `billing:topup`, `billing:write`, `ssh:read`, `reputation:write`, and `providers:write` so a pasted connector token can inspect billing and provider status without charging a card, enumerating existing SSH keys, or moving a payout. Grant those scopes explicitly via OAuth consent or a dedicated client credential when needed. An agent on a Quick Connect key can also ask for one with `request_permission`: it returns an approval link that only you can approve, signed in, on a page that names what the permission allows. Top-up (`billing:topup`) is available to a Quick Connect key only that way.

## Managing access

You can stop an AI client from accessing Xcelsior at any time by revoking its OAuth session in your client or from **Dashboard → Settings → Connect AI Agents**.

### Claude Code

**To log out**:

```bash
claude mcp logout xcelsior
```

**To clear authentication interactively**:

Run `/mcp` inside Claude Code and choose **Clear authentication**.

**To remove the Xcelsior MCP server completely**:

```bash
claude mcp remove xcelsior
```

Run `claude mcp logout xcelsior` first so stored OAuth tokens are cleared before removing the server entry.

**To manage tool permissions**:

Run `/permissions` inside Claude Code to view, allow, or block specific Xcelsior MCP tool rules.

### Codex CLI

**To clear or sign out of the server's authentication tokens**:

```bash
codex mcp logout xcelsior
```

**To delete the Xcelsior MCP server configuration**:

```bash
codex mcp remove xcelsior
```

Always run `logout` first, as removing the server entry alone can leave stored tokens behind.

### How access is protected

- **Xcelsior-hosted authentication**: You sign in and grant access on an Xcelsior-controlled page, never inside the AI client.
- **OAuth 2.1 with PKCE & RFC 9728**: Public clients authenticate with Proof Key for Code Exchange and resource-bound audience tokens (`https://mcp.xcelsior.ca/mcp`).
- **Per-tool scope enforcement**: Every tool declares its exact `allOf` / `anyOf` scope requirement. There is no blanket wildcard scope.
- **Idempotency & replay protection**: Spending and settlement tools (`request_provider_payout`, `top_up_wallet`, `claim_reputation_milestones`) are keyed in PostgreSQL so a network retry never double-pays or double-charges.
- **Secret redaction at the boundary**: Provider and billing tools strip processor identifiers (`stripe_account_id`, `onboarding_url`, PayPal `merchant_id`/`payer_id`, Wise `wise_recipient_id`/`fingerprint`, and Stripe `client_secret`) before responses enter model context.

## Troubleshooting

| Problem | Cause & solution |
| --- | --- |
| **The client asks to authenticate again.** | Your access token expired, the session was revoked, or scopes changed. Re-run your client's authentication flow (`/mcp` in Claude Code or `codex mcp login xcelsior`). |
| **A tool is listed but returns `insufficient_scope`.** | Your connection does not carry the scope required for that tool (for example, Quick Connect tokens omit `billing:topup`, `ssh:read`, `reputation:write`, and `providers:write`). Reconnect via OAuth and approve the required permission group, or let the agent call `request_permission` and approve the link it gives you. |
| **A launch tool returns `approval_required` with a `plan_id`.** | Spending actions create a bounded launch plan first. Approve the plan in the Xcelsior dashboard (or check its status with `get_mcp_action_status`), then re-run with the approved `plan_id`. |
| **A Wise payout is `queued` instead of paid immediately.** | Unlike Stripe and PayPal (which settle job-by-job), Wise payouts are batched once per provider and require platform admin approval after any 72-hour recipient cool-off expires. Use `get_wise_status` to check `queued_cad`, `minimum_payout_cad`, and `recipient.payable`. |
| **The MCP server does not connect.** | Check that the URL is exactly `https://mcp.xcelsior.ca/mcp`, your client supports Streamable HTTP (`2025-03-26`) and OAuth 2.1, and your firewall/network allows outbound HTTPS to `mcp.xcelsior.ca` and `xcelsior.ca`. |
