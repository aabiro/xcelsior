## Overview

The worker agent runs on each GPU host machine. It handles host registration, version reporting, telemetry, and job execution within sandboxed containers.

## Installation

Register the host in the dashboard (**Hosts → Register Host**) and create an API key or OAuth client under **Settings → API & SSH**. Then, on the GPU host:

```bash
# Guided setup (Node.js 18+): hardware checks, registration, pricing, service install
curl -fsSL https://xcelsior.ca/install.sh | bash

# Without Node.js: installs the worker service directly
curl -fsSL https://xcelsior.ca/install.sh | bash -s -- --agent-only
```

The installer checks the NVIDIA driver and Docker's NVIDIA runtime, asks for the Host ID and credentials, verifies the ed25519 signature of every agent module it downloads, and installs the `xcelsior-worker` systemd service. It finishes by waiting for the first heartbeat and reporting the admission state.

| Path | Contents |
|------|----------|
| `~/.xcelsior/worker.env` | Host ID, scheduler URL, credentials (mode 600) |
| `~/.xcelsior/worker_agent.py`, `~/.xcelsior/lib/` | Signed agent modules |
| `~/.xcelsior/venv/` | Pinned Python dependencies |
| `/etc/systemd/system/xcelsior-worker.service` | The service; `systemctl cat xcelsior-worker` shows it |
| `/var/lib/xcelsior/` | Worker state (attempt journal), created by systemd |

To update the agent: `curl -fsSL https://xcelsior.ca/install.sh | bash -s -- --update`.

## Configuration

`~/.xcelsior/worker.env` holds the settings. Edit it, then run `sudo systemctl restart xcelsior-worker`:

```bash
XCELSIOR_HOST_ID=my-gpu-01
XCELSIOR_SCHEDULER_URL=https://xcelsior.ca
# Option A: API key
XCELSIOR_API_TOKEN=your-api-key
# Option B: OAuth machine client
XCELSIOR_OAUTH_CLIENT_ID=your-client-id
XCELSIOR_OAUTH_CLIENT_SECRET=your-client-secret
```

If both auth methods are present, the worker prefers OAuth client credentials.

## Checking the Agent

```bash
systemctl status xcelsior-worker
journalctl -u xcelsior-worker -f
```

On start, the agent will:
1. Detect local GPU hardware via NVML
2. Register with the scheduler (`PUT /host`)
3. Report software versions (`POST /agent/versions`)
4. Begin telemetry loop (every 5 seconds)
5. Poll for assigned jobs

## Telemetry

The agent reports these metrics every 5 seconds:

| Metric | Unit | Description |
|--------|------|-------------|
| `gpu_utilization` | % | Current GPU compute usage |
| `temperature` | °C | GPU die temperature |
| `memory_used` | GB | GPU memory in use |
| `memory_total` | GB | Total GPU memory |
| `power_draw` | W | Current power consumption |
| `ecc_errors` | count | ECC memory error count |
| `pcie_tx` | MB/s | PCIe transmit bandwidth |
| `pcie_rx` | MB/s | PCIe receive bandwidth |

## Job Execution

When a job is assigned:

1. Agent pulls the job specification
2. Downloads any required artifacts
3. Starts a Docker container with GPU passthrough
4. Applies isolation based on job tier:
   - `community` → standard runc
   - `secure`/`dedicated` → gVisor (runsc)
5. Monitors execution, streams logs
6. Uploads output artifacts on completion

## Security Features

### Mining Detection

The agent monitors for cryptocurrency mining patterns:
- GPU utilization sustained above 95%
- PCIe TX bandwidth under 5MB/s (mining doesn't output much data)
- Triggers: immediate job kill + reputation penalty

### Egress Firewall

Containers run with restricted network access:
- Only allowed destinations: scheduler API, artifact storage
- No direct internet access from job containers
- All egress logged for audit

### Version Gating

The scheduler enforces minimum versions:
- NVIDIA Driver ≥ 535.0
- Docker ≥ 24.0
- runc ≥ 1.1.14
- nvidia-ctk ≥ 1.17.8

Hosts failing version checks remain in `pending` state and cannot receive jobs.
