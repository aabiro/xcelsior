## Overview

Xcelsior is built to be operated by software, not just by people clicking. There are
three ways in, and they reach the same platform:

- **Bring your own agent** via the hosted [MCP server](#mcp-integration), Claude,
  Cursor, ChatGPT, or anything that speaks Model Context Protocol.
- **Use ours** — [Xcel AI](#xcel-ai-the-in-app-assistant) is a tool-calling assistant
  in the dashboard, no client and no config.
- **Point any LLM at the docs** — machine-readable specs follow the
  [llms.txt specification](https://llmstxt.org) alongside a full OpenAPI 3.1 document.

## llms.txt Endpoint

```bash
GET https://xcelsior.ca/llms.txt
```

Returns a structured text document optimized for LLM consumption, covering:
- API overview and authentication
- All endpoint groups with request/response formats
- Error codes and handling
- Rate limiting details

## OpenAPI Specification

The full machine-readable API spec:

```bash
GET https://xcelsior.ca/openapi.json
```

Returns OpenAPI 3.1.0 with:
- client-facing endpoint definitions only (70 paths / 79 operations)
- 50+ request/response schemas
- Security scheme definitions
- Server URLs (production + development)
- **Serverless inference** (`/api/v2/serverless/*`, `/v1/serverless/{id}/*`) plus legacy `/api/v2/inference/endpoints` aliases

## Using with AI Agents

### Claude / ChatGPT

Point your AI agent to the llms.txt endpoint:

```
Read https://xcelsior.ca/llms.txt for the Xcelsior API documentation.
```

### Custom Integrations

Use the OpenAPI spec to generate client code:

```python
import json
import httpx

spec = httpx.get("https://xcelsior.ca/openapi.json").json()
# Use spec to drive API calls
```

### MCP Integration

Xcelsior ships a **hosted MCP server** at `https://xcelsior.ca/mcp` (Streamable HTTP). Agents connect with a Bearer token from an OAuth machine client, no local install required.

**Setup:** Dashboard → Settings → **Connect AI Agents** (or visit [xcelsior.ca/mcp](https://xcelsior.ca/mcp)).

**Cursor config:**

```json
{
  "mcpServers": {
    "xcelsior": {
      "url": "https://xcelsior.ca/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_OAUTH_ACCESS_TOKEN"
      }
    }
  }
}
```

**Curated agent tools** (not a raw OpenAPI dump): `list_available_gpus`, `create_instance`, `should_i_run_this`, `run_training_job`, `get_wallet_balance`, and more. Destructive tools require `confirm: true`; use `should_i_run_this` for cost + wallet checks first.

The public OpenAPI spec remains available for custom integrations:

```json
{
  "name": "xcelsior",
  "description": "GPU compute orchestration",
  "api_spec": "https://xcelsior.ca/openapi.json"
}
```

## Xcel AI, the in-app assistant

Not every user wants to wire up an MCP client. **Xcel** is a tool-calling assistant
built into the dashboard at [`/dashboard/ai`](https://xcelsior.ca/dashboard/ai). It
drives the platform in natural language for anyone already signed in, with no client,
no key, and no config, and it reaches the same class of capability as the MCP server.

**34 tools across the product surface:**

| Area | Examples |
|------|----------|
| Compute | `launch_job`, `stop_job`, `list_jobs`, `get_job_details`, `get_host_status` |
| Discovery | `recommend_gpu`, `get_gpu_availability`, `search_marketplace`, `get_benchmarks` |
| Cost | `estimate_cost`, `get_pricing`, `get_billing_summary`, `get_invoices` |
| Storage | `list_volumes`, `list_checkpoints` |
| Credentials | `create_api_key`, `revoke_api_key`, `add_ssh_key` |
| Provider side | `get_payout_history`, `get_reputation`, `get_sla_status` |

**Write actions require explicit confirmation.** Any tool that spends money, launches
compute, or mints a credential returns a *pending confirmation* instead of executing.
The user approves it, and only then does it run. Confirmations are signed, single-use,
bound to the requesting user, and they expire.

| Endpoint | Purpose |
|----------|---------|
| `POST /api/ai/chat` | Send a message; returns the reply plus any tool calls made |
| `POST /api/ai/confirm` | Approve or reject a pending write action |
| `GET /api/ai/suggestions` | Context-aware next-step prompts |
| `GET /api/ai/conversations` | Conversation history |

A separate support assistant (`POST /api/chat`) does RAG over the product docs. It
answers questions but holds no tools and cannot change anything.

### Which surface should I use?

Use **MCP** when the agent lives outside Xcelsior and needs to coordinate us with
other systems. Use **Xcel AI** when you want the same reach with nothing to install,
which in practice is what most people try first. Use the **REST API** directly when
you are writing the automation yourself.

## Serverless inference for agents

For LLM workloads (chat completions, async jobs, streaming), use the **serverless inference** surface instead of batch `/v1/inference`:

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://xcelsior.ca/v1/serverless/{endpoint_id}/openai/v1",
    api_key="xcel_...",  # per-endpoint key from dashboard
)
response = client.chat.completions.create(
    model="meta-llama/Llama-3-8B-Instruct",
    messages=[{"role": "user", "content": "Explain spot vs on-demand GPU pricing."}],
)
```

Async job flow (RunPod-style): `POST /v1/serverless/{id}/run` → poll `GET /v1/serverless/{id}/status/{job_id}` → optional `GET .../stream/{job_id}` for SSE tokens.

Management (create endpoints, keys, usage): `client.serverless.*` in the TypeScript SDK or `/api/v2/serverless/endpoints`.

## Rate Limits

When integrating AI agents, be aware of rate limits:
- **30 requests/second** per IP address
- **20 concurrent connections** per IP
- **Burst**: up to 50 requests allowed in bursts
- Health endpoints (`/healthz`, `/readyz`) are exempt
