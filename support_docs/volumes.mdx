# Persistent Volumes

Because Xcelsior instances are ephemeral (especially Spot instances), you need a way to persist your datasets, model weights, and outputs. **Persistent Volumes** provide scalable network storage that can be attached to any instance.

## Overview

- **Capacity:** Up to 2,000 GB (2TB) per volume.
- **Billing:** Flat rate of $0.03 CAD per GB-month, prorated to the second.
- **Persistence:** Volumes persist independently of the instance lifecycle. You can detach a volume from a stopped instance and attach it to a new one.
- **Technology:** Backed by enterprise-grade NFS servers.

## Security & LUKS Encryption

All persistent volumes on Xcelsior are highly secure. You have the option to enable **LUKS2 Encryption** when creating a volume. 
- When encrypted, the volume is created as a LUKS2 loopback image.
- Encryption keys are stored securely in the central Xcelsior database using Fernet encryption and are **never** written to the NFS server's disk.
- When you attach an encrypted volume to an instance, Xcelsior securely handles the `luksOpen` process on the fly. 

## Attaching Volumes

Volumes can be attached in two ways:

1. **Launch-time Attach:** Select the volume when creating a new instance. The scheduler will automatically mount the volume into your container (default path: `/workspace`) before your code starts running.
2. **Hot Attach:** Attach a volume to an already-running instance via the API or dashboard. The volume will be dynamically mounted into the running container without requiring a restart.

## Team Storage

If you are operating within a Team Workspace, volumes belong to the team and draw from the team's shared wallet. The standard limit is 2,000 GB total storage across a maximum of 50 volumes per team.
