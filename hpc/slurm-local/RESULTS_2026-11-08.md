## C. Suite

All 26 cases pass. The two new ones:

- **SEC-1:** a job on the tower ran as `xclslurm` and got `Permission denied` creating its own `~/.ssh`. Afterwards, `id` through the key was still refused.
- **SEC-2:** scripts with `#SBATCH --chdir` or with `--output` aimed at the service account's `~/.ssh` were refused with exit 126 and no job id. The gate logged each refusal.

The gate's journal shows 213 allowed requests in the run. Its only denials were the manual probes and SEC-2's scripts.

## What the real run found that the rehearsal couldn't

1. **Rollback could have killed a Docker container's database.** Rollback ended with `pkill -x mariadbd` for stray daemons. That matches across PID namespaces, and on the tower it matched mempool's `mariadbd` inside Docker. Found in the first tower dry run, before any rollback ran there. Rollback now kills only host-namespace, non-container processes.
2. **A reinstall left MariaDB without system tables.** MariaDB's AppArmor profile (setuid/setgid commented out) denies the uid change `mariadb-install-db` makes during the package's postinst. Purging the package leaves the profile loaded, so the first install worked and the reinstall didn't. The tables are now created as the `mysql` user when missing, and rollback unloads the stale profile.
3. **Rollback resurrected `/etc/default/slurmd`** on the ASUS (above). Fixed.
4. **The sleep-target preflight check failed falsely** with all four targets masked (`systemctl show` prints blank lines between units). Fixed.

## Observations

- **The tower's GPU is shared.** The health check logged five non-Slurm processes on the RTX 3060: MPS, pxl-publisher, pe-test-gpu-worker and two in a Docker container. It logs them and doesn't drain. GPU-1 and POD-1 measured a shared GPU.
- **Slurm 25.11.2 still lacks the eight CVE fixes in 25.11.8.** This is acceptable for a single-operator cluster on the tailnet, not for tenants.
- **Tower RAM:** `TOWER_MEM_MB` is 8192. Raise it to 16384 after the planned 32 GB upgrade, following the README.

The cluster was left running, with services disabled at boot.
